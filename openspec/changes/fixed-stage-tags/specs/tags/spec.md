# Spec Delta

## REMOVED Requirements

### Requirement: 优先复用已有标签

**Reason**: 自由复用让模型不断造出新说法，筛选列表不稳定。阶段名单改为产品固定，不再把项目里已经出现过的标签交给模型续写。
**Migration**: 模型请求改为附上固定九个阶段。已有索引里的自由说法不自动改写；正文未变时仍按「正文未变时手改标签保持」保留。

## ADDED Requirements

### Requirement: 标签只能取自固定阶段

新写入索引的主题标签 MUST 属于下列九个阶段，顺序固定：立项计划、产品调研、产品设计、需求分析、技术设计、技术实现、缺陷管理、上线运营、项目复盘。一段仍 MUST 是 0 到 2 个。模型返回的任一标签不在这九个里，或超过 2 个时，该次输出 MUST NOT 写入索引；已有上一轮时 MUST 保留上一轮，并告知这段没有更新。用户新增标签时 MUST 只能选择这九个阶段，MUST NOT 通过自由输入造出新说法。用户可以删除段上已有的非阶段标签。正文未变且用户未再改时，已有的非阶段标签 MUST 保持不变。

#### Scenario: 模型自造说法不会写入

- **WHEN** 模型对一段返回标签「上线」，且该段已有上一轮标签「立项计划」
- **THEN** 索引中该段标签仍是「立项计划」
- **AND** 用户被告知这段没有更新

#### Scenario: 手改只能选择阶段

- **WHEN** 一段已有标签「立项计划」，用户再新增「技术实现」
- **THEN** 该段标签为「立项计划」和「技术实现」

#### Scenario: 自由输入的新说法不生效

- **WHEN** 用户试图给一段新增「上线」
- **THEN** 这次新增不生效
- **AND** 段上原有标签不变

#### Scenario: 可以删掉旧的非阶段标签

- **WHEN** 一段上已有标签「上线」，用户删除它
- **THEN** 该段不再带有「上线」

### Requirement: 模型请求附上固定阶段

会触发模型的段，其请求 MUST 附上全部九个阶段名称。请求 MUST NOT 再把项目里已经出现过的自由标签当作可选说法附上。

#### Scenario: 请求包含九个阶段而不是旧说法

- **WHEN** 项目里已有旧标签「上线」，且新段正文会触发模型
- **THEN** 该段的请求内容包含「立项计划」和「项目复盘」
- **AND** 请求内容不把「上线」列为可选标签
