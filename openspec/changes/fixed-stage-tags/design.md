# Design

## Context

见 `proposal.md` 的 Why。当前模型请求带 `projectTags`（`collectTags` 扫出来的自由说法），解析只拒绝超过 2 个或格式非法的标签。段上新增标签是自由文本框。操作栏筛选项就是这些收集到的说法。

`decisions` 仍要求模型只给程序切好的段打标签，标签在旁路索引。本变更不写 `decisions` 的 delta。

## Goals / Non-Goals

**Goals:**

- 九个阶段作为唯一的新标签词表，提示词、解析、手改和筛选项共用同一份常量与同一顺序。
- 模型输出里出现词表外说法时，整段结果不写入，沿用现有「解析失败则保留上一轮并提示没有更新」的路径。
- 筛选项与项目里实际出现过的标签脱钩。

**Non-Goals:**

- 不把标签从「段」改成「整篇文档一个阶段」。按阶段找文档仍是：筛到这些段，再进入所在文件。
- 不让用户增删阶段名。名单只在产品里改。
- 不把旧索引里的自由说法自动改写成某个阶段，也不在再分析时因正文未变而清掉它们。
- 不停止模型打标签。

## Decisions

### 词表是代码常量，不是项目数据

九个阶段写在一处常量，顺序与规格一致。不写入项目索引，用户也不能在界面里增删。

考虑过允许每个项目自己改阶段名单。这会把「每次长得不一样」从模型转移到项目配置，和「相对固定、打开就能对上」相反，所以不做。

### 模型仍从词表里选，而不是改由用户唯一指定

提示词列出全部九个阶段，并写明只能使用这些名称。`parseModelPayload` 在超限检查之外拒绝词表外的名称；任一标签非法则整次输出失败。任务嗅探的失败处理不另开一条路：标签非法时这段的任务同样不写入，上一轮整段记录保留。

考虑过取消模型打标签、只留人手选阶段。那要改 `decisions` 里「模型给切好的段打标签」，这次确认没有授权改这条拍板，所以模型继续选择，只是不能自造说法。

上一轮标签若是旧说法，仍作为上一轮参照放进请求，但不作为可选词表。

### 手改：新名称必须在词表内，旧名称可以删

`updateSegmentTags` 在「不超过 2 个」之外，拒绝结果里新出现的词表外名称。已经在段上的旧说法可以原样留下或被删掉。界面把自由输入改成阶段下拉，可选项是尚未加在该段上的阶段。

### 筛选下拉直接用词表

操作栏不再调用 `collectTags` 生成选项。「全部」后面按常量顺序排九个阶段。查询语义不变：段的 `tags` 包含所选阶段即命中。旧说法仍留在段上，但不会成为筛选项，选不到「上线」这类名称。

## Risks / Trade-offs

- [旧标签留在段上却进不了筛选] → 不自动改写。段旁仍显示并可删除。正文再变并重新分析成功后，模型输出会整段换成 0 到 2 个阶段。
- [模型把阶段名写偏一次就整段不更新] → 与今天超限或字段非法的处理相同，提示「没有更新」，避免写入半截结果。
- [现有测试大量使用「上线」「立项」「实现」等自由说法走模型桩] → 走模型写入的期望改成九个阶段之一；只为构造旧索引或验证筛选项不含旧说法时，才保留词表外名称。

## Migration Plan

不迁移索引。回滚就是恢复自由标签的提示、解析、手改和 `collectTags` 筛选项；已经写成阶段名的段在回滚后仍是普通字符串标签，可以继续被筛到。
