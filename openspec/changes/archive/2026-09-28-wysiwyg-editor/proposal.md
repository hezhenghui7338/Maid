# Proposal

## Why

打开一篇文档时，源码和预览分成左右两屏，用户要在源码里改、到预览里看。这种分离让人根本不想写。编辑应当像 Typora 那样：屏幕上就是排好版的文档，输入和修改就发生在这一屏上。

## What Changes

- **BREAKING** 编辑面从「源码 + 预览分屏」改为单屏所见即所得。打开文档时只看到一篇已渲染的文档，文字、结构修改都在这一屏完成。
- **BREAKING** 不再提供源码模式，也不提供源码与所见即所得的切换。
- 磁盘上的文件仍是 Markdown。标签、任务和时间信息仍只在旁路索引里，不写回正文。
- 检索高亮、邻段和列表回跳落到这一屏文档上，按源码字符范围映射。不再要求定位到独立源码视图。
- 数学公式、示意图的专门编辑仍不进入当前版本。

用户已确认：当前版本就改这条拍板，并接受「平时只有一屏、没有源码切换」。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `decisions`：改「源码编辑加实时预览」。编辑体验改为单屏所见即所得，禁止分屏预览和源码切换。同步改「非目标留在范围外」：去掉「所见即所得编辑」这一条非目标。其余拍板（原文不写回、分段、再分析、手动分析、macOS、模型接口）不动。
- `editor`：用「单屏所见即所得编辑」替换「源码与预览同时可见」。基础八类 Markdown 仍须在同一屏按语义显示并可编辑。
- `search`：原文高亮、邻段和集中列表回跳从「源码中」改为所见即所得文档中的对应范围。

## Impact

- 前端：`src/ui/App.tsx` 的分屏布局、`src/ui/editor.tsx`、`src/ui/preview.tsx`、`src/ui/app.css`。
- 检索回跳：`HighlightRange` 与 `scrollTo` 仍按 Markdown 源码偏移，但展示在所见即所得文档上。
- 验收：`TDD.md` 的 ED-01、ED-02、ED-03、ED-05，以及检索回跳相关的 SR 用例。
- 分段、索引、模型分析不改行为。不改 `PRD.md`。
