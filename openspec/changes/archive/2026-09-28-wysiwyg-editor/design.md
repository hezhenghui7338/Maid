# Design

## Context

见 `proposal.md` 的 Why。现在 `src/ui/App.tsx` 把 `SourceEditor`（CodeMirror，文档即 Markdown 字符串）和 `Preview`（markdown-it 只读 HTML）左右并排，并用滚动比例互相同步。检索高亮和回跳用的是 Markdown 字符偏移，画在 CodeMirror 上。分段、再分析和「原文不写回」都以这份字符串及其内容哈希为准。

## Goals / Non-Goals

**Goals:**

- 一屏编辑：去掉预览栏和双栏滚动同步。
- 屏幕上的文档按标题、段落、列表、引用、代码块、表格、链接、强调排版，用户直接在这一屏输入。
- 编辑器内部文档继续是 Markdown 字符串。未改动的正文保持原字节，以便内容哈希和段偏移仍然有效。
- 检索高亮与 `scrollTo(偏移)` 仍作用在这一份文档上。

**Non-Goals:**

- 不引入富文本模型，也不在保存时整篇重新序列化 Markdown。
- 不提供源码模式开关。
- 不做公式和示意图。
- 不改分段、索引、分析、设置。

## Decisions

### 用现有 CodeMirror 做 Typora 式单屏

文档模型保持现在的 CodeMirror。视觉层用装饰把语法记号收起来，让块呈现出对应语义：不在光标所在块时，标题记号、强调记号、链接地址等不占视觉主体；光标进入该块时，露出该块的 Markdown 记号以便修改。这一屏就是编辑面，不再另挂只读预览。

选择它，是因为检索、分段和过期判断都按 Markdown 字符偏移和内容哈希工作。换成 HTML 所见即所得再序列化回 Markdown，会改写用户没动过的字节，使未改段被当成已改。

备选：Milkdown / TipTap。视觉更接近排版器，但往返序列化不能保证未改段字节不变，和高亮偏移也会错位。不采用。

### 去掉预览栏

`App` 只挂这一份编辑器。删除预览组件在主界面上的位置、滚动比例同步和预览专用样式。`Preview` 若不再被引用则删掉，markdown-it 仅在仍有测试或别处使用时保留。

### 高亮继续用源码偏移

`HighlightRange` 的 `from` / `to` 不变。命中与邻段装饰画在同一份 CodeMirror 文档上，`scrollTo` 仍滚到字符偏移。集中列表点击打开文件后定位的是这一屏，不是另一块预览。

### 光标所在块露出记号，其余块保持排版

这是 Typora 的块内编辑，不是源码模式。不增加切换按钮。表格和代码块在光标离开时显示为整块，光标进入时回到可改的 Markdown 行，避免把表格或围栏从中间拆开。

## Risks / Trade-offs

- [表格、链接的装饰难做到和 HTML 预览一样稳] → 以「语义可见、同一屏可改」为完成线。光标进入块时退回该块原文，保证改得动。
- [装饰隐藏记号后，测试若只找源码文本会失败] → 先改 `TDD.md` 的 ED-01、ED-02、ED-03、ED-05 和 SR-02、SR-03，再改 `tests/stories.test.tsx`。ED-03 双栏滚动同步删除。ED-05 改为在文档里输入会改动正文。
- [只读打开不得改写文件] → 装饰不改变文档字符串；`onChange` 只来自用户编辑。

## Migration Plan

只改界面。已有项目、索引和 Markdown 不迁移。回退即恢复分屏编辑器与预览组件。
