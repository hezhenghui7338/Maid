# Proposal

## Why

底栏把「需要重新分析」和当前模型、接口地址放在同一行。过期提示和正在用哪套接口对写作没有帮助，看起来像实现细节漏到了界面上。

## What Changes

- 底栏不再显示「需要重新分析」。
- 底栏不再显示当前模型名和基地址。点按该文字打开 API 设置的入口一并拿掉。
- 工具栏上的「API 设置」保留，仍是改基地址、密钥和模型的入口。
- 底栏继续显示当前文件路径、分析消息，以及有检索时的命中位置。
- 文档过期时仍不用上一轮的段范围高亮当前正文。程序仍只标记过期，不在后台调用模型。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `reanalysis`：修改「过期不沿用旧高亮」。过期时界面不再标明需要重新分析；不用旧范围高亮这一点不变。
- `model`：增加底栏不展示当前模型名和基地址。不改调用方式，也不改 API 设置的保存位置。

## Impact

- 不改 `decisions`。「分析由用户手动触发」仍成立：过期只在程序内标记，不自动发模型请求。拿掉的是底栏文案，不是这条拍板。
- 前端：`src/ui/App.tsx` 底栏与 `.api-status`。
- 验收：`TDD.md` 的 AN-08；`tests/stories.test.tsx` 里对「需要重新分析」的断言。
- 分析、索引和高亮判断不受影响。
