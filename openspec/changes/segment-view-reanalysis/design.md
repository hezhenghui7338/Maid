# Design

## Context

见 proposal.md。写作屏的正文是 `App.tsx` 里同一份 `draft`，由 `SourceEditor`（CodeMirror 加 `livePreview`）整篇渲染。分段在 `segmentMarkdown`：标题是边界，不进入段正文；段带 `headingPath`、`ordinal`、`start`、`end`。全文分析是顶栏按钮调用 `analyzeDocument`：先 `alignSegments`，未变段不调模型，成功且无失败时才把 `processedContentHash` 写成整篇哈希。`isFileStale` 只比这份哈希；过期时高亮范围清空。

## Goals / Non-Goals

**Goals:**

- 写作屏内切换整篇与按段，两边改的是同一份 `draft`。
- 按段再分析复用现有对齐和模型写回，但模型只打所选段。
- 非整对一时按段分析不改索引，并提示改用全文分析。

**Non-Goals:**

- 不在按段卡片上改标签或任务状态。整理屏保持原样。
- 标题行不在段卡片里编辑。标题仍在整篇展示里改。
- 正文未变不强制重跑模型。
- 不改 `decisions`，不把分析改成自动触发。

## Decisions

- 展示状态放在写作屏，两个按钮：「整篇」「按段」。按段用 `segmentMarkdown(draft)` 列出段。卡片标题是只读的标题路径。段正文用现有 `SourceEditor`，`fileKey` 用标题路径加段内序号，避免输入时重建。`onChange` 用该段当时的 `start`/`end` 把新文本拼回整篇 `draft`，段与段之间的标题和空白留在原处。
- 输入过程中不因这次按键重切所在卡片，以免光标被整段替换打断。失焦、切换展示或点击分析时，用当前 `draft` 重新分段。
- 顶栏「分析」继续调用 `analyzeDocument`，不传段范围。
- `analyzeDocument` 增加可选的段目标：标题路径加段内序号。未传时行为与现在相同。传入时先照旧分段并对齐，再只保留与目标一对一的那一对：`changed` 才发模型，写回只替换该段记录；`unchanged` 不发模型，标签和任务不动。同一文件其余段记录、未匹配列表和 `processedContentHash` 都不改。目标在对齐结果里是 `fresh`，且没有同身份的上一轮段时，按新段调用模型，请求不带旧任务，只写入这一段。目标对不上上一轮（切开、合并，或新鲜段顶替了原身份）时不发请求、不改索引，消息为需要改用全文分析。
- 一对一的判定：对齐后的草稿段，其标题路径和段内序号等于用户所点的身份，且配对上的上一轮段也是同一身份；或者该草稿是 `fresh` 且索引里本来就没有这个身份。其余情况视为不再一对一。

备选：按段分析成功后重算整篇哈希并打开高亮。不做。甲的长度一变，乙的源码范围就过期；只改所选段时不能把文件标成整篇已分析，否则过期高亮规则会用旧范围套新正文。

## Risks / Trade-offs

- [只分析甲之后，乙已过期但高亮仍整篇关闭，直到用户再做一次全文分析] → 全文分析会按现有规则跳过未变段。按段成功后的提示说明其他过期段未分析。
- [段卡片只含段正文，用户在卡片里加标题不会改到原标题行，可能切出新段] → 失焦后重分段；若所点身份不再一对一，分析按钮走「改用全文分析」，不发模型请求。
- [拼回 `start`/`end` 时拼错会改到相邻段] → 切片只用这次分段给出的范围，标题和空白不放进卡片编辑器。
