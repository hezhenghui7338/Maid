# Proposal

## Why

写作屏只有整篇所见即所得，分析按钮也只对整篇跑一轮。用户改某一段、或只想重跑某一段时，只能在整篇里找位置，并连带把同一文件里其他已过期的段也送去分析。

## What Changes

- 写作屏增加展示切换：整篇所见即所得，与按当前文档的程序分段逐段展示。两种都是渲染后的编辑，磁盘上仍是同一份 Markdown。不增加源码区，也不提供源码模式。
- 按段展示时，用户可以编辑某一段的原文。编辑写回该文件的 Markdown，标签、任务和段时间仍只留在旁路索引。
- 顶栏「分析」仍是全文再分析：重新分段、对齐，正文未变的段不调用模型。
- 按段展示中的某一段可以单独再分析：模型请求只针对这一段。同一文件里其他段即使正文已过期，也不调用模型，已有标签、任务和手改保持不动。
- 用户所点的这一段若正文未变且仍一对一，沿用现有规则，不调用模型。本次不把「正文未变仍强制重跑」纳入范围。
- 拍板 `decisions`「单屏所见即所得」不改：按段展示仍是同一写作屏上的渲染编辑，不是源码与预览的切换。`decisions`「原文不写回」「分析由用户手动触发」不改。

用户已确认：当前版本就做；切换发生在写作屏内；某一段再分析只把这一段送给模型。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `editor`：写作屏可在整篇与按段展示之间切换。按段展示中编辑段原文，并写回该文件的 Markdown。
- `reanalysis`：在全文再分析之外，增加只处理用户所选一段的再分析。其他段不调用模型。

## Impact

- 写作屏：`src/ui/App.tsx`、`src/ui/editor.tsx`、`src/ui/app.css`。整理屏的筛选、改标签和改状态不改。
- 分析入口：`src/core/analyze.ts` 需能只对一段调用模型，并避免把文件级 `processedContentHash` 提前写成整篇已分析。
- 验收：`TDD.md` 增补写作切换与按段分析用例。不改 `PRD.md`，不改 `decisions`。
