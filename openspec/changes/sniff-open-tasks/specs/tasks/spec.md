# Spec Delta

## ADDED Requirements

### Requirement: 只把未完成事项收成任务

会触发模型的段，其请求 MUST 只根据这一段正文判断要不要建任务。请求 MUST 写明：只有这段里还没做完的事项才建任务。原文已经写明解决、完成、修好，或写明放弃、取消、不做时，请求 MUST 要求任务为空，MUST NOT 要求收成「已完成」或「已取消」。请求 MUST NOT 要求根据同一文档的其他段做这个判断。

#### Scenario: 已写明解决时请求要求不建任务

- **WHEN** 一段正文会触发模型
- **THEN** 该段请求写明：原文已写明解决、完成或修好时，任务为空
- **AND** 请求不要求把这种情况收成「已完成」

#### Scenario: 已写明放弃时请求要求不建任务

- **WHEN** 一段正文会触发模型
- **THEN** 该段请求写明：原文已写明放弃、取消或不做时，任务为空

#### Scenario: 请求不引用其他段

- **WHEN** 同一文档里还有别的段落，且当前段会触发模型
- **THEN** 该段请求不要求用其他段判断有没有未完成事项

### Requirement: 未完成事项的建议状态

会触发模型的段，其请求 MUST 写明未完成事项的建议状态：原文写明正在做、未完成或执行中时建议「进行中」；只是待办、没有写做到哪一步时建议「待确认」。请求 MUST NOT 要求把这类新嗅探的事项标成「已完成」或「已取消」。

#### Scenario: 请求区分待确认和进行中

- **WHEN** 一段正文会触发模型
- **THEN** 该段请求写明：正在做、未完成或执行中时建议「进行中」
- **AND** 请求写明：只是待办、没有写做到哪一步时建议「待确认」
