# Design

## Context

见 proposal.md。当前系统提示在 `src/core/model.ts` 的 `createOpenAIClient`：列出四态，并写「没有可执行事项时 task 为 null」，没有判据。`analyzeDocument` 把模型返回的 `task` 原样写入；返回 `null` 时该段没有任务。正文未变的段不发请求。解析层仍接受四态，非法状态整段不写入（现有 AN-09 / AI-03）。

## Goals / Non-Goals

**Goals:**

- 把「只收未完成事项」和「待确认 / 进行中」写进每次会触发模型的请求，使测试能断言提示原文。
- 不改写回、分段、手改和检索。

**Non-Goals:**

- 不用关键词表替模型做第二次判断。
- 不把其他段的正文放进请求。
- 不改 `fixed-stage-tags` 的标签规则；只避免互相抹掉提示句。

## Decisions

### 判据放在系统提示，不事后改模型结果

模型仍是嗅探者。系统提示写清：只为本段里还没做完的事项建任务；已写明解决、完成、修好，或放弃、取消、不做，则 `task` 为 null，不要建议「已完成」或「已取消」；正在做、未完成、执行中则建议「进行中」；只是待办则建议「待确认」。`parseModelPayload` 和 `analyzeDocument` 的写回保持不动。若模型仍返回合法的「已完成」，现有写回继续接受，以免破坏「正文已变以模型输出写回」。

备选是按字面过滤「已修复」再删任务。那样会和模型输出抢权威，也会漏掉变体说法。不采用。

### 验收看请求原文

沿用 TG-03 的做法：分析会触发模型的一段，断言该次请求包含上述判据，并且没有要求用其他段判断。不接真实模型。

### 与标签提示分开改

只追加任务判据。现有「优先使用给定的已有标签」一句先留着。`fixed-stage-tags` 若已把标签句改成九个阶段，合并时两段都保留。

## Risks / Trade-offs

- [模型不听提示] → 规格锁的是请求里的判据，不是某次模型的实际输出。听不听取决于所用模型。
- [正文未变的误收任务清不掉] → 这是现有「正文未变不调用模型」。要清掉须改这段后再分析，或用手改状态。本变更不另开一条删除任务的入口。
- [第一问括号里的「建议已完成」与第二问冲突] → 以第二问为准：已写明解决的不建任务。已写明放弃同样不建任务，因为不属于还没做完。手改仍可标「已完成」和「已取消」。

## Migration Plan

无索引迁移。已有任务留到该段正文变更并再次分析，或用户手改状态。回退就是恢复原来的系统提示。
