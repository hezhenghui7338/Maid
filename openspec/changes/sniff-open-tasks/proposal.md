# Proposal

## Why

手动分析时，模型既漏掉段里还没做完的事项，也会把原文已经写明解决的内容收成任务，而且建议状态对不上这段在说什么。提示里只有「没有可执行事项时 task 为 null」，没有判据。

## What Changes

- 仍由用户手动分析。模型仍只看当前这一段的正文，不读同一篇里的其他段，也不在后台自动分析。
- 只有这段里还没做完的事项才建成任务。原文已经写明解决、完成、修好，或写明放弃、取消、不做的，任务 MUST 为空，MUST NOT 收成「已完成」或「已取消」。
- 收成任务时，建议状态只在「待确认」和「进行中」里选：原文写明正在做、未完成、执行中，建议「进行中」；只是待办、没说做到哪，建议「待确认」。
- 四态仍保留。用户手改仍可以把已有任务改成「已完成」或「已取消」。模型返回合法状态时，写回规则不变。
- 正文没有改过的段继续不调模型，不会因为这次新规则重判。要清掉误收的任务，需要这段正文有变更后再分析。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `tasks`：补上「什么才算要纳入的任务」和「建议状态怎么从本段措辞得出」。不改 `decisions`：分析仍须用户触发；模型仍只给程序切好的段嗅探任务；索引仍不写回 Markdown。不改 `reanalysis` 的对齐和「正文未变不调用模型」。

## Impact

- 模型系统提示：`src/core/model.ts`。只补任务判据，不改标签句。进行中的 `fixed-stage-tags` 若先改同一段提示，合并时两边都要留下。
- 写回路径不变：模型返回 `task: null` 时该段没有任务；返回合法状态时仍按现有规则写入。
- 验收：在 `TDD.md` 增加提示词用例，并回归 `bc-20260928-sniff-open-tasks`。不改分段，一段仍至多一条任务。
