# Spec Delta

## MODIFIED Requirements

### Requirement: 标签与状态查询

**来源**: PRD §12

用户 MUST 能在整屏整理工作区按主题标签、按任务状态，或两者一起查询。查询范围 MUST 是当前项目内全部已分析文档，MUST NOT 只限当前打开的文件。集中展示的 MUST 是段，不是从段里拆出的第二份任务正文。任务筛选只是多了一个状态条件。写作屏 MUST NOT 在文档旁或文档下再放一套同样的查询控件。

#### Scenario: 标签与状态一起只命中同时满足的段

- **WHEN** 甲、乙带标签「上线」，甲的任务为「进行中」，乙的任务为「已完成」，用户同时选择「上线」和「已完成」
- **THEN** 只有乙出现在整理工作区

#### Scenario: 查询覆盖项目内其他文件

- **WHEN** 当前打开的是甲所在文件，乙在同一项目的另一篇已分析文档里，且乙带有所选标签
- **THEN** 整理工作区列出乙

### Requirement: 集中列表按原文顺序回跳

**来源**: PRD §12

集中展示 MUST 把命中段按原文顺序排成列表，并作为整理工作区的主体。点击一项 MUST 离开整理工作区，回到写作屏，并定位到该段在文档中的范围。按状态筛选时，结果 MUST 只列出处于该状态的段，并且同样能跳回该文档。

#### Scenario: 列表顺序与点击回跳

- **WHEN** 用户在整理工作区打开标签「上线」的集中展示并点击乙，且甲在乙前
- **THEN** 列表顺序是甲然后乙
- **AND** 点击乙后写作屏打开乙所在文档，并定位到乙的范围
- **AND** 列表展示的是段，不是另写的一份任务正文

#### Scenario: 按进行中筛选后回跳

- **WHEN** 用户在整理工作区筛选「进行中」并点击结果，且只有甲处于该状态
- **THEN** 只有甲出现
- **AND** 点击后回到写作屏中甲所在的位置

## ADDED Requirements

### Requirement: 整理工作区占整屏

检索与任务管理 MUST 共用一个整理工作区。用户 MUST 能从顶栏在写作屏和该工作区之间切换。整理工作区打开时 MUST 占据写作主区域的位置，MUST NOT 作为文档下方的固定高度条。标签筛选、状态筛选和命中段列表都在这一屏里。

#### Scenario: 整理时看不见文档下方的结果条

- **WHEN** 用户从顶栏打开整理工作区并按标签查询
- **THEN** 命中段列表铺在这一屏的主区域
- **AND** 写作中的文档不与这条列表同时挤在同一主区域

#### Scenario: 从写作进入整理

- **WHEN** 用户正在写作屏，从顶栏切换到整理
- **THEN** 主区域变为整理工作区
- **AND** 写作中的文档不再占着主区域
