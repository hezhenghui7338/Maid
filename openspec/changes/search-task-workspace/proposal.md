# Proposal

## Why

标签搜索和任务管理是 Maid 的关键能力，现在却和当前文件的段编辑挤在编辑区底部一条固定高度的抽屉里，像一块试做区域。用户要在这一整屏里找回段、改状态和标签，再回到写作。

## What Changes

- **BREAKING** 写作与整理分成两个整屏。顶栏可以在两者之间切换。写作时主区域是文件树和正在编辑的文档，不再在文档下方挂检索或任务抽屉。
- **BREAKING** 标签筛选、状态筛选、命中段列表、改标签和改任务状态，都发生在同一个整理工作区。该工作区占写作区以外的整屏，跨项目内全部已分析文档，不再只服务当前打开的文件。
- 点击列表中的段，切换到写作并定位到该段。高亮、邻段和上下键移动的查询语义不变。
- 任务说明仍不能在整理界面改写。不把整理工作区做成表格，也不做成可改写任务正文的独立卡片。
- 拍板 `decisions`「非目标留在范围外」里「不以表格或独立任务卡片作为任务正文的编辑器」保持不变。本次不改这条拍板。

用户已确认：当前版本就改；搜索和任务合成一个整屏，写作是另一个整屏；点结果回到写作并定位。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `search`：查询入口和集中列表从操作栏加文档下方抽屉，改为整屏整理工作区。回跳改为切回写作中的文档。
- `tasks`：改状态和改标签发生在该整屏工作区。任务说明仍不可改。
- `editor`：写作屏不再与检索或任务列表分占同一主区域。

## Impact

- 前端布局：`src/ui/App.tsx`、`src/ui/app.css`。查询函数 `searchHits` 已是全项目范围，可继续复用。
- 进行中的 `fixed-stage-tags` 也改标签筛选项的内容。本变更只改筛选项所在的屏，不改选项从哪来。两处都落地时，整理工作区里的标签选项遵循阶段标签那条规格。
- 验收：`TDD.md` 的 SR-01 至 SR-04、TK-02、TK-03、TK-05，以及界面故事里依赖底部抽屉的检索和改状态用例。分段、索引写回、分析触发不改。不改 `PRD.md`，不改 `decisions`。
