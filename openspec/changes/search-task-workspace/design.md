# Design

## Context

见 `proposal.md` 的 Why。现在 `src/ui/App.tsx` 把主区域做成 `1fr + 190px`：上面是 `SourceEditor`，下面是 `.drawer`。顶栏的「标签」「状态」一变，`searchHits` 的结果就以截断按钮堆在这条抽屉里；当前文件的全部段也排在同一条里，用来加删标签和改任务状态。`searchHits` 已经按文件路径、再按段在原文中的起点排序，范围是整个项目索引。高亮和滚动仍由写作屏里的 `activeHit` 驱动。未匹配任务今天只列出当前文件的。

`decisions` 里「不以表格或独立任务卡片作为任务正文的编辑器」不改。进行中的 `fixed-stage-tags` 只决定标签选项的词表，本变更不改词表。`wysiwyg-editor` 已改编辑器本体；本变更不把它改回分屏预览。

## Goals / Non-Goals

**Goals:**

- 顶栏切换「写作」和「整理」。整理打开时，主区域整块换成整理工作区。
- 整理工作区里完成筛选、看命中段、改标签、改状态；点击段回到写作并定位。
- 写作屏只留下文件树和文档。

**Non-Goals:**

- 不改查询命中条件、高亮范围、邻段、索引写回。
- 不新增任务说明编辑，不做表格或可改写正文的任务卡片。
- 不改分析、分段、模型请求。

## Decisions

1. **用一个界面状态在两屏之间切换，默认写作。** 顶栏放「写作」「整理」。整理时卸掉文件树和编辑器，主区域只留工作区，这样工作区才是整屏，而不是编辑器旁边再开一栏。写作时挂回现在的文件树和编辑器，并删掉 `.stage` 的第二行固定高度。
   备选：整理叠在编辑器上当浮层。浮层仍然让写作占据底层，和「写作是另一屏」不符。
   备选：搜索和任务再分成两屏。用户确认合成一屏。

2. **筛选搬进整理工作区，查询仍调用 `searchHits`。** 标签、状态默认都是「全部」。无条件时现有函数会返回全部段，整理屏用这份列表同时承担浏览和筛选，不再另做只含当前文件的段列表。点段的正文区域时切回写作、打开对应路径，并把当前命中设为这一条，沿用已有高亮和 `scrollTo`。标签按钮和状态下拉阻止这次跳转。
   备选：筛选留在顶栏。顶栏会在写作时也占着查询，规格要求写作屏不再放这套控件。

3. **每一条是可读的段，不是调试用的单行按钮。** 沿用现有纸色，把路径和标题做成次要信息，段正文换行显示，标签和状态跟在同一条里。列表是这一屏的主体，留出可读的行距。任务说明只展示，没有输入框。
   备选：表格列对齐状态。那会把任务管理做成表格编辑器，和拍板冲突。

4. **写作屏在已有查询时响应上下键。** 命中之间的移动留在写作中的文档上，继续只停在命中段并带出邻段。整理屏里的上下键只滚动列表，不偷偷改写作位置。

5. **未匹配列表放到整理工作区，范围改为当前项目全部未匹配。** 抽屉去掉之后，原来挂在当前文件下的「关闭」不能消失。数据本来就在索引里，不新增存储。

6. **标签选项沿用实现当时的收集方式。** 若 `fixed-stage-tags` 已把选项改成九个阶段，整理工作区直接用那份列表，不在这里改回 `collectTags`。

## Risks / Trade-offs

- [界面故事现在在编辑器下方找段、标签输入和状态] → 先切到整理再操作；查询和写回断言保持不变。
- [「全部 / 全部」下列出项目里每一段，长项目会一屏很长] → 工作区内部滚动；仍按原文顺序，不另做分页。
- [和 `wysiwyg-editor` 都改了回跳措辞] → 归档时保留「回到写作屏并定位」，不恢复源码分屏。
- [点状态时误触发行跳转] → 状态和标签控件单独处理点击，不触发打开文档。

## Migration Plan

只改界面。索引和 Markdown 不迁移。回退是恢复顶栏筛选和文档下方抽屉。
