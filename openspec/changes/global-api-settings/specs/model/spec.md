# Spec Delta

## ADDED Requirements

### Requirement: API 设置全局一份

API 设置 MUST 是应用级的一份，包含基地址、密钥和模型。保存后 MUST 对所有项目生效。切换项目或新建项目 MUST NOT 要求用户重新配置。系统 MUST NOT 把 API 设置写入项目目录。尚未保存过设置时，默认基地址 MUST 仍是 `http://localhost:11434/v1`，密钥 MUST 可以是任意非空字符串。

#### Scenario: 换项目后仍用同一套接口

- **WHEN** 用户在项目 A 把基地址、密钥和模型改成非默认值并保存，然后切换到项目 B 或新建项目
- **THEN** 界面上的基地址、密钥和模型仍是刚才保存的那一份
- **AND** 在项目 B 中分析时，请求发往该地址并带上该密钥

#### Scenario: 未打开项目也能保存

- **WHEN** 用户尚未打开任何项目，修改基地址、密钥和模型并保存，随后打开一个项目并分析
- **THEN** 请求发往刚才保存的地址并带上该密钥

#### Scenario: 没有历史设置时用默认 Ollama

- **WHEN** 应用还没有任何已保存的 API 设置，用户打开一个项目并分析
- **THEN** 请求发往 `http://localhost:11434/v1` 的 chat completions
- **AND** 使用默认的非空密钥

### Requirement: 从当前项目迁入一次

尚不存在全局 API 设置，且当前已打开项目里已有 API 设置时，系统 MUST 把这份设置迁为全局设置。迁入完成之后，系统 MUST NOT 再读取任何项目内的 API 设置。

#### Scenario: 打开已保存设置的项目时迁入

- **WHEN** 还没有全局设置，且当前项目里已保存过非默认的基地址和密钥，用户打开该项目
- **THEN** 全局设置变为该项目里的那一份
- **AND** 切换到另一个没有自己设置的项目后，分析仍发往迁入的地址并带上该密钥

#### Scenario: 迁入后忽略项目内改动

- **WHEN** 全局设置已经存在，而某个项目内的 API 设置与全局不一致
- **THEN** 分析和设置界面使用全局设置
- **AND** 项目内那份设置不会覆盖全局
