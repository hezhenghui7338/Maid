# Design

## Context

现在应用数据目录下的 `projects/` 是项目列表：每个子目录是一个项目，文件命令都带项目名，索引写在该项目的 `.maid/index.json`。侧栏是这个项目里的 Markdown 相对路径扁平列表。`searchHits` 扫整份项目索引。见 proposal.md 的 Why。

文件系统边界仍在 `src-tauri/src/projects.rs` 与 `src-tauri/src/lib.rs`。前端入口是 `src/ui/App.tsx`。

## Goals / Non-Goals

**Goals:**

- 命令和界面都以 `projects/` 为唯一存储根，相对路径从根算起。
- 侧栏展示文件夹和 `.md` 文件，可嵌套。
- 查询、手改标签和任务、以及送给模型的已有标签，都按当前选中节点过滤。
- 旧项目目录在第一次打开存储根时归并进根索引。

**Non-Goals:**

- 不提供移动，不打开外部文件夹。
- 不改 `decisions`，不改编辑器是不是所见即所得。
- 不改 API 设置的存放位置。进行中的 `global-api-settings` 负责把它移出项目目录；本变更只去掉「必须先选项目」。
- 不决定整理工作区是抽屉还是整屏。那是 `search-task-workspace` 的事。本变更只收紧命中范围。

## Decisions

### 存储根就是原来的项目目录

继续使用应用数据目录下的 `projects/`，不再把它的第一层子目录解释成项目。这样已有资料仍在原处，只是少了一层「进入项目」。

备选是另建一个 workspace 根再把旧项目拷进去。多一次搬迁，失败时两边各有一份，所以不采用。

### 索引只保留根上的一份

读写只认 `projects/.maid/index.json`。文件记录里的 `path` 一律相对存储根。

第一次打开时，若根索引还不存在，则扫描存储根下一层子目录里的 `.maid/index.json`：每条文件路径加上该子目录名，文件 id 原样保留，未匹配记录同样加前缀，然后写成根索引。扫描后删除这些子目录里的 `.maid`，避免下次再当一份独立索引。若根索引已存在，跳过归并。

备选是运行时同时读多份索引。查询和改名要跨文件改前缀，容易写漏，所以不采用。

### 选中节点是一条相对路径加类型

前端保存当前选中：文件夹、文件，或未选中。未选中等于范围是存储根。这个选择写入现有 `state.json`，替换里面的 `current` 项目名，重新打开时恢复范围。

过滤规则：文件节点只留 `path` 全等的文档；文件夹节点只留 `path` 等于该文件夹，或以「文件夹名加 `/`」开头的文档。不用单纯的字符串前缀，避免 `note` 命中 `notebook/a.md`。

`searchHits` 增加这个范围参数。打标签时收集「已有标签」也用同一过滤，再交给现有分析请求。

### 新建只收一个名称

文件夹名和文件名沿用现有项目名校验：去掉首尾空白，拒绝空名、`.`、`..`、以 `.` 开头、以及路径分隔符。文件名没有 `.md` 时补上。新建落点由选中节点决定，不接受用户输入的相对路径。

文件夹改名和删除在 Rust 里对目录操作。索引侧按上面的路径边界改前缀或删掉命中文档。产品内不提供把节点拖到另一个文件夹。

### 入口跟进行中的文件栏变更对齐，但不保留项目

若 `file-sidebar-context-menu` 尚未合入，本变更自己把侧栏做成树：加号选出「新建文件」或「新建文件夹」，右键提供导入、改名、删除、导出，且没有移动。若该变更已经合入，则删掉顶栏项目控件，并把加号从「只新建文件」改成可以新建文件或新建文件夹；右键在文件夹上同样能改名和删除。两处不要同时保留「新建项目」。

## Risks / Trade-offs

- [归并中途失败，根索引写好但子目录 `.maid` 还在] → 根索引一旦存在就不再归并。失败时不要留下半截根索引；写入使用临时文件再替换。
- [同名文件 id 在两个旧项目里都出现] → 归并时若 id 已存在，后者整条跳过并记一条用户可见说明，不覆盖已写入的记录。
- [与 `search-task-workspace` 同时改查询入口] → 范围过滤放在 `searchHits`，不绑死抽屉或整屏。那边改布局时继续调用带范围的查询。

## Migration Plan

发布后的第一次启动执行一次根索引归并。没有旧项目索引时直接使用空的根索引。回退代码不能把根索引拆回各项目目录；回退前需保留归并前的数据副本。本变更不自动做这份副本以外的降级。
