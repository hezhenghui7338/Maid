# reanalysis Specification

## Purpose

描述用户手动再分析时如何对齐旧段、何时调用模型、写回什么，以及过期时如何提示。来源是原 PRD 第 11 节。

## Requirements

### Requirement: 对齐顺序

**来源**: PRD §11.1

再分析 MUST 先重新分段，再在同一文件 id 下把新段与上一轮索引对齐。对齐依据 MUST 依次为内容哈希是否相同、标题路径是否相同、文本是否相似。哈希相同的段 MUST 继承对应的旧标签和旧任务，MUST NOT 因为段内序号变化而配错。

#### Scenario: 哈希相同则直接一对一

- **WHEN** 一段正文与上一轮某段哈希相同，即使段内序号变了
- **THEN** 该段继承对应的旧标签和旧任务

### Requirement: 非一对一进入未匹配

**来源**: PRD §11.1

一段被切成两段，或两段合成一段，都 MUST NOT 算一对一。旧任务 MUST 进入「未匹配」，MUST NOT 自动挂到其中某一段，也 MUST NOT 被删除或静默丢弃。切开或合并后新出现的段 MUST 按没有上一轮记录来分析。其余对不上的旧任务同样 MUST 进入「未匹配」，直到用户处理，或后续某轮重新形成一对一对齐。

#### Scenario: 删除段落后旧任务进入未匹配

- **WHEN** 用户从正文删除一段已有任务的内容并再次分析
- **THEN** 该任务出现在未匹配列表
- **AND** 说明和删除前的状态都还在
- **AND** 它没有挂到别的段上

#### Scenario: 切开不继承任务

- **WHEN** 一段已有「进行中」任务的正文被切成两段并再次分析
- **THEN** 旧任务在未匹配列表，状态仍是「进行中」
- **AND** 切开后的两段都不自动带着这条旧任务
- **AND** 两段的模型请求不包含这条旧任务

#### Scenario: 合并不继承任务

- **WHEN** 相邻两段各有一条任务，改写后下一轮变成一段
- **THEN** 原来的两条任务都在未匹配列表
- **AND** 合并后的新段按没有上一轮记录分析
- **AND** 模型请求不携带这两条旧任务

### Requirement: 正文未变不调用模型

**来源**: PRD §11.2

本段正文未变，且与上一轮仍是一对一时，系统 MUST 沿用索引中的标签和任务状态，MUST NOT 调用模型。用户手改过的结果同样 MUST 保持不变。只修改其他段时，未改段 MUST 被跳过。

#### Scenario: 正文未变时手改保留

- **WHEN** 一段已分析，用户把手改状态和标签留下，正文不再改动，然后再次分析
- **THEN** 这段没有模型请求
- **AND** 状态和标签仍是手改结果
- **AND** 手改标记仍在

#### Scenario: 未改的段在再分析时被跳过

- **WHEN** 文档有甲、乙两段都已分析，用户只修改甲的措辞后再次分析，且甲仍能一对一
- **THEN** 乙没有模型请求，标签和状态与再分析前相同
- **AND** 甲有一次模型请求

### Requirement: 正文已变以模型输出写回

**来源**: PRD §11.2、§11.3

本段正文已变且与上一轮仍是一对一时，系统 MUST 调用模型。输入 MUST 包含段正文、标题路径、上一轮标签、上一轮任务状态，以及这些值是否来自用户手改。上一轮状态只作参照。写回索引时 MUST 以模型本轮输出为准，即使用户此前手改过该状态。手改标记 MUST 随这次写回失效。此后若正文未变，MUST NOT 再把旧手改当作冻结值。只处理更新时间晚于处理时间的段，以及本轮因切开或合并而需要重新判定的段。

#### Scenario: 模型状态覆盖手改

- **WHEN** 一段状态被手改为「进行中」后，正文改成仍能一对一对齐的新句子并再次分析
- **THEN** 发给模型的内容包含上一轮标签、上一轮状态「进行中」，以及该状态来自手改
- **AND** 写回索引的状态是模型本轮输出
- **AND** 手改标记不再冻结这段

### Requirement: 新段不带旧任务

**来源**: PRD §11.2

没有上一轮记录的新段 MUST 调用模型，且请求 MUST NOT 带旧任务。已有段若正文未变，MUST NOT 调用模型。

#### Scenario: 新增正文不携带旧任务

- **WHEN** 用户在已分析文档的标题下新增一段从未出现过的正文，然后分析
- **THEN** 新段的模型请求没有旧任务
- **AND** 正文未变的已有段不调用模型

### Requirement: 模型输出结构

**来源**: PRD §11.3

模型输出 MUST 是固定结构：不超过 2 个主题标签，以及可空的一条任务。任务 MUST 包含说明、原文摘录、建议状态和简要理由。没有可执行事项时，任务 MUST 为空。摘录 MUST 来自该段正文。摘录不在该段正文中时，这条结果 MUST NOT 作为有效任务写入索引；已有上一轮时 MUST 保持上一轮有效记录，并告知这段没有更新。

#### Scenario: 摘录不在正文中则不写入

- **WHEN** 模型返回的摘录不在该段正文中
- **THEN** 这条结果不作为有效任务写入索引
- **AND** 上一轮中该段的有效记录保持不变
- **AND** 界面告知这段没有更新

### Requirement: 处理时间在分析成功后更新

**来源**: PRD §7.3、§11.3

分析完成后，系统 MUST 更新这段的处理时间。被处理的段的处理时间 MUST NOT 早于分析前的更新时间。之后这些段 MUST NOT 因同一份正文被标成待分析。

#### Scenario: 成功分析后不再标成待分析

- **WHEN** 一次分析成功
- **THEN** 被处理段的处理时间不早于分析前的更新时间
- **AND** 之后这些段不再因同一份正文被标成待分析

### Requirement: 过期不沿用旧高亮

**来源**: PRD §11.4

索引里的源码范围 MUST 只对应当时的正文。文档的更新时间晚于已分析段的处理时间时，界面 MUST 标明需要重新分析。过期期间 MUST NOT 用上次的段范围高亮当前正文。

#### Scenario: 已修改未分析时不再用旧范围高亮

- **WHEN** 文档已分析并能按某标签高亮一段，用户随后修改正文并保存，且不分析
- **THEN** 界面标明需要重新分析
- **AND** 该标签不再用上次的源码范围高亮当前正文
